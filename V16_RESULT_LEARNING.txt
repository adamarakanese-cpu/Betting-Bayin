BETTING BAYIN V16.0 FINAL PRE-BET
RESULT TRACKING + PERFORMANCE CALIBRATION

What was added
- Canonical prediction_results table in PostgreSQL/SQLite.
- Duplicate customer requests for the same match/market/selection do not inflate performance samples.
- Automatic final-result checker runs in the background once per hour.
- TheSportsDB is checked first; Groq web-search research is a fallback for lower leagues.
- Same-day TheSportsDB scores are accepted only when the event is explicitly finished.
- Web-search settlement requires exact team matching, completed status, a source URL, and >=0.85 confidence.
- Final-score settlement supports every market currently generated by the V15/V16 model:
  1X2, Double Chance, BTTS, Totals, Home/Away Team Totals,
  Home/Away Clean Sheet, At Least One Team To Score, Correct Score.
- Integer total pushes settle as VOID.
- Unsupported markets become UNRESOLVED rather than being guessed.
- Admin manual fallback:
  /pending
  /checkresults
  /settle ID 2-1
  /settle ID win|loss|void
  /performance

Performance learning
- Uses only unique, verified settled predictions.
- Measures hit rate, Brier score, actual-odds ROI and profit units.
- Calibration feedback is disabled until enough samples exist.
- Selection-level calibration requires >=18 decisive results.
- Market-family fallback requires >=30 decisive results.
- Historical adjustment is Bayesian-shrunk and hard-capped at +/-4 percentage points.
- Correct Score is excluded from automatic historical probability adjustment.
- Performance feedback never blocks normal tip generation if the database is unavailable.

Important
This is calibration feedback, not a guarantee of future results. Betting outcomes remain uncertain.
Estimated-odds picks are excluded from ROI calculations because they are not actual bookmaker prices.
